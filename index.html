Lesson 1

Under the Hood

Hardware vs. Software: How Computers Actually Think

Key Objectives

  • Understand the role of CPU, RAM, and Storage (SSD/HDD).
  • Learn how components interact to run a program.
  • Settle the difference between volatile and non-volatile memory.

Press to enter the lesson.

Lesson 1: Intro

Introduce the subject: Computers are in everything, but how do they actually process information? Today, we go under the metal cover.

Teaching Tip: Ask them to list all the things in the room that have a computer inside (phones, smart bulbs, microwave). Tell them they all share the same basic architecture.

Press Down to explain the concepts using the Kitchen Analogy.

The Computer Kitchen

The Chef (CPU)

Does the actual thinking and processing. Multi-cores are like adding extra arms to chop, stir, and cook at once.

The Countertop (RAM)

Fast, temporary workspace. Everything active is kept here. Volatile—wiped clean when the kitchen closes.

The Pantry (Storage)

Huge long-term storage (SSD/HDD) holding all files and programs. Non-volatile. Slower to fetch ingredients from.

Assistant Chef (GPU)

Specialized worker dedicated entirely to drawing visual elements and complex graphics (gaming & 3D).

The Kitchen Story (Script)

Tell the kids: "Imagine you are running a busy restaurant kitchen."

  • The Chef is the CPU: The chef does all the chopping and cooking. A chef with a clock speed of 4 GHz does 4 billion actions per second. 8 cores mean the chef has 8 arms to work simultaneously.
  • The Counter is RAM: When the chef makes a salad, they lay the tomatoes and lettuce on the counter because it's fast to grab. If the counter is tiny, the chef must keep running back to the pantry, slowing everything down. At night, the counter is wiped clean.
  • The Pantry is Storage (SSD/HDD): It holds 100 bags of flour. It survives power shutdowns. HDD is a slow pantry at the end of a long hallway; SSD is a cabinet right next to the chef.

Ask them: "If we have a fast Chef but a tiny counter, what happens?" (The chef bottlenecks because they have to swap ingredients back and forth to the pantry).

Lab: The $1,000 Custom PC

Project Time

Open PCPartPicker.com. Choose a client profile and build a compatible PC under $1,000.

Gamer (Ethan)

Needs smooth frame rates. Spend 35-40% of the budget on the GPU. Decent mid-range CPU.

Creator (Maya)

Edits 4K videos. Prioritize a multi-core CPU, at least 32GB RAM, and a fast 2TB+ SSD.

Coder (Sarah)

Needs speed and multitasking. Integrated graphics is fine. Focus on a high-end **CPU**, **32GB RAM**, and a premium **SSD**.

Lab Guidance

Instruct the kids to select one of the clients above. Help them launch PCPartPicker.

Rules:

  1. Budget is exactly $1,000.
  2. Must select CPU, Motherboard, RAM, Storage (SSD), Case, PSU, and GPU (if needed).
  3. PCPartPicker must show "Compatibility: No issues or incompatibilities found" in green at the top.

Let them debate components. Have them justify why they chose a specific motherboard socket or memory speed.

Lesson 1 Check-In

Questions

  1. If you open 20 Chrome tabs and the system lags, which hardware part is full?
  2. What is the main physical difference between an HDD and an SSD?
  3. What does "volatile" mean in reference to memory?

Quiz Answer Key

  1. RAM: The kitchen countertop has run out of space. The computer has to swap data to the slower storage drive.
  2. Moving Parts vs. Flash Chips: An HDD has spinning platters and read heads (moving parts); an SSD uses microchips (flash memory) and has no moving parts, making it 5-10x faster.
  3. Temporary: It means data is lost when power is turned off (like RAM). Non-volatile (SSD/HDD) retains data without power.

Lesson 2

Files, Folders & The Cloud

Managing Data Locally and Globally

Key Objectives

  • Learn how file extensions govern file behavior.
  • Master paths: Absolute vs. Relative address routing.
  • Understand virtualization, the cloud, and data center footprints.

Lesson 2 Intro

In this lesson, we study how computers structure files and where they go when stored in "the cloud". We will also practice moving files using the CLI (Command Line Interface).

Press Down to explain file paths and cloud basics.

Paths, Extensions, & The Cloud

Extensions & Paths

  • Extensions: `.exe` vs `.jpg` labels that tell the OS which decoder to use.
  • Absolute Path: Full location from root (`C:\Users\Docs\file.txt`).
  • Relative Path: Location relative to current spot (`Docs\file.txt`).

Cloud & Virtualization

  • The Cloud: Simply "someone else's computer" in a data center.
  • Virtualization: Splitting one physical server into dozens of independent "Virtual Machines" (VMs). Saves massive power.

Teaching Details

Filing Cabinet Analogy: Storing a file locally is putting paper in a drawer in your room. The file path is drawer -> folder -> page. Storing in the cloud is mailing that paper to a massive secure warehouse with robotic arms (servers) that fetch it when requested.

Ask them: "If I rename song.mp3 to song.docx, does it play?" (No, MS Word will load the binary music code and display pages of random gibberish symbols because it can't decode audio).

Lab Part 1: CLI Folder Rescue

Activity

Run the setup script from the lesson guide in PowerShell to create `messy_folder`. Now, organize it using only the command line:

Useful Commands

`cd `: Change directory
`mkdir `: Create new folder
`ls` or `dir`: List files in folder
`mv `: Move file

Organize the downloads into three folders: Documents, Images, and Installers based on file extensions.

CLI Lab Guide

Paste the setup script from `lesson_02_files_folders_cloud.md` into PowerShell to create the messy files. Then sit back and guide them:

  1. Have them navigate with: cd C:\Apps\SummerAcademy\curriculum\comp101\messy_folder
  2. View the mess with: ls
  3. Make folders: mkdir Documents, Images, Installers
  4. Move the files (e.g. mv *.jpg Images or move one by one). Let them type and make typos. Explain why tab-completion is a lifesaver!

Lab Part 2: Datacenter Math

Fermi Estimation Challenge

  • Premise: A modern data center holds 50,000 servers.
  • Each server consumes 500 Watts of electricity.
  • Calculate: What is the power draw of the facility in Megawatts (MW)?
  • Comparison: If an average house uses 1.2 kW, how many homes' worth of electricity does this data center devour?

Datacenter Math Answers

  • Total Watts: 50,000 servers * 500 Watts = 25,000,000 Watts.
  • Conversion to MW: 25,000,000 Watts = 25,000 kW = 25 Megawatts (MW).
  • Comparison: 25,000 kW / 1.2 kW = 20,833 homes.

Point out: That's a medium-sized town's worth of power just for one datacenter holding photos and videos!

Lesson 2 Check-In

Questions

  1. What is the command to create a new folder in PowerShell?
  2. What is the difference between an Absolute Path and a Relative Path?
  3. True or False: The Cloud is a wireless space in the sky where data floats.

Quiz Answers

  1. mkdir (make directory).
  2. Absolute: complete address starting from the root (like C:\). Relative: address starting from where you currently are.
  3. False: The cloud is made of physical, energy-intensive warehouses with real computers, fiber optic cables, and air conditioning.

Lesson 3

How the Internet Works

Packets, DNS, and the Global Network Pipeline

Key Objectives

  • Understand packet fragmentation and TCP/IP delivery.
  • Learn how DNS servers act as the "phonebook" of the web.
  • Use diagnostic tools to trace real packet routes across the globe.

Lesson 3 Intro

Today we demystify how a website gets onto their screens. We'll trace the routing and look at submarine cables.

Press Down to discuss routing and the postcard analogy.

The Global Pipeline

Packets & Routing

Files are sliced into packets (1500 bytes each) stamped with source & destination IPs. Routers act as traffic cops, forwarding them along different paths. Reassembled at the destination.

Domain Name System

DNS translates human-friendly domain names (`google.com`) into computer-readable numerical IP addresses (`142.250.190.46`). Without DNS, names fail to load.

Postcard Analogy (Script)

Explain: "Imagine you want to mail a 100-page notebook to Tokyo, but the post office only accepts single postcards."

  • You tear the pages out, put numbers on them, stamp them with the Tokyo address, and drop them in the mail.
  • They travel on different planes/trucks. Your friend receives them, sorts them by page number, and reassembles the notebook.
  • If page 45 is lost, your friend sends a card back: "Send page 45 again." That is TCP/IP.

Ask: "How do packets cross the Atlantic Ocean? Satellites?" (No! Undersea fiber-optic cables on the ocean floor carry light signals across oceans).

Lab: Tracing the Route

Activity

Open PowerShell and run these diagnostic network utilities:

Network Tools

  • Lookup IP: nslookup google.co.jp
  • Test Latency: ping google.co.jp (look at the speed in milliseconds)
  • Trace Route: tracert www.u-tokyo.ac.jp

Analyze the hops. Look for airport codes (e.g. LHR, NRT) in the router names and lookup public IPs on ipinfo.io.

Lab Instructions

Guide the kids through running the commands. It's fascinating to see their packet bounce from their home router, through regional servers, then jump to submarine cables, and arrive in Tokyo in under 200 milliseconds.

Explain: Ping is round-trip time. Light in a fiber cable takes about 67ms just to cross the planet in a straight line, which shows how fast fiber connections are.

Lesson 3 Check-In

Questions

  1. What system translates website names to numerical IP addresses?
  2. What happens if this system goes offline? Can you still reach sites?
  3. If a gaming server ping is 250ms, is that better or worse than 20ms?

Quiz Answers

  1. DNS (Domain Name System).
  2. Yes: If you know the exact IP address, you can type it into the browser bar and it will load. Only name translation is broken.
  3. Worse: 250ms means a quarter of a second lag. 20ms is much faster, meaning actions feel instantaneous.

Lesson 4

The History of Work

From Floppy Disks to Real-Time Cloud Syncing

Key Objectives

  • Contrast the local file era with modern database syncing.
  • Understand version renaming problems and merge conflicts.
  • Learn how servers sync multiple typists using algorithms.

Lesson 4 Intro

Let's talk about how software has changed how people collaborate. We went from floppy disk exchange to typing in the same cell at the same time.

Press Down to look at history and how syncing works.

How Syncing Works

The Desktop Era

Files saved to local hard drives. Collaborating meant emailing files. Created naming chaos like: `report_final_v2_edit_DAD.docx`. If two people edited separately, merging was manual.

The Collaboration Era

Master file lives on a cloud database. Keystrokes are sent as tiny data updates. Algorithms like Operational Transformation (OT) referee conflicts, shifting letters so edits do not overwrite.

Blackboard Analogy (Script)

Explain: "In the old days, I wrote on a page in a notebook and handed it to you. While you had the notebook, I couldn't write. That is local file saving."

"Today, we use Google Docs. It’s like standing in front of a giant blackboard with chalk. We can both write and erase at the same time. The server coordinates where our hands are so we don't scribble on the exact same spot."

Lab: Collaboration Battle

Challenge

Battle 1: Email Versioning

Write a story. Parent writes paragraph 1, emails it. Teens write paragraph 2, email it back. Meanwhile, parent writes paragraph 3 separately. Try to combine them without copy-paste errors!

Battle 2: Cloud Syncing

Open one shared Google Doc. Set a timer for 3 minutes. Both write and edit at the exact same time: Parent does paragraphs 1 & 3; Teens do 2 & 4. Edit each other's typos live!

Lab Guidance

This is a fun activity that demonstrates the friction of the old way of working. Let them feel the frustration of renaming files and trying to merge two people's edits into one document.

In Part 2, watch the latency of cursors. Point out how fast updates sync.

Lesson 4 Check-In

Questions

  1. What is a "merge conflict"?
  2. Where is the master file stored when using Google Docs or Notion?
  3. Why do heavy applications like video games or 3D modeling software still run locally rather than in the cloud?

Quiz Answers

  1. Merge Conflict: When two people edit the exact same line of a file separately, and the computer cannot determine which edit is the correct one, requiring a human to choose.
  2. Cloud Server: Stored in a database on a data center, not on the user's hard drive.
  3. Performance/Latency: They require 100% of local CPU, GPU, and RAM power to render frames instantly. Network lag would make real-time interaction laggy and unresponsive.

Lesson 5

Visual Communication

Principles of Clear Layout: Briefs vs. Slide Decks

Key Objectives

  • Understand visual hierarchy and typography (Serif vs. Sans-Serif).
  • Learn the proper use of negative (white) space.
  • Distinguish between a presentation slide deck and a written brief.

Lesson 5 Intro

Today is about design as a form of logic. How do we present information so that a reader's brain processes it with the least amount of effort (cognitive load)?

Press Down to discuss typography and layouts.

Visual Hierarchy

Typography & Space

Serif: Has decorative feet (Georgia, Times). Best for print books. Sans-serif: Clean (Arial, Inter). Best for digital slides. Never use more than 2 font families. Use negative space so the eyes can breathe.

Brief vs. Slide Deck

Written Brief: Meant to be read alone. High density, full paragraphs, structured text. Slide Deck: Supports a live speaker. Highly visual, low text density (billboard test). Never read paragraphs off a slide.

The Billboard Test (Script)

Explain: "Imagine driving at 60 mph. You see a billboard. If it has 3 paragraphs of small text, do you read it?" (No, you'd crash!).

"A slide deck is a billboard. The audience should scan the slide in 3 seconds, get the point, and look back at you. If they are reading your slide, they are not listening to you."

Lab: The Voyager 1 Redesign

Challenge

Read the boring wall of text about Voyager 1 in the lesson guide. Complete two tasks:

Task 1: The Brief

Format it on a single page with a title, subheadings, bullet points for key stats, and bold text for crucial terms. Make it scan-friendly.

Task 2: The Deck

Turn the same information into a 5-slide deck. **Strict rule:** maximum of **15 words** per slide! Use massive numbers and image concepts.

Lab Guidance

This is a great practical design lesson. Let them copy the text from `lesson_05_visual_communication.md`.

For the deck, enforce the 15-word limit strictly! If they write "Voyager 1 was launched on Sept 5, 1977 and is currently 15 billion miles away," they will run out of words. Teach them to write: "1977" (huge text) and "Launch Date" (small text), then verbally explain the rest. This forces them to act as presenters.

Lesson 5 Check-In

Questions

  1. What is the difference between a Serif and a Sans-Serif font?
  2. What is "cognitive load"?
  3. True or False: A slide deck should contain every word you plan to say so the audience can follow along.

Quiz Answers

  1. Serif has decorative feet at the ends of letters (good for print books). Sans-Serif is flat and clean (good for digital screens).
  2. Cognitive Load: The mental effort required to process information. Crowded slides or messy layouts increase cognitive load, making readers lose focus.
  3. False: Slides should be visual billboards. The speaker provides the details; slides only anchor the main point.

Lesson 6

Spreadsheet Mastery

Thinking in Structured Data: Formulas, References, and Budgets

Key Objectives

  • Understand columns, rows, cell grids, and data types.
  • Distinguish between relative (`A1`) and absolute (`$A$1`) cell references.
  • Write logical functions: `SUM`, `AVERAGE`, `IF`, and `XLOOKUP`.

Lesson 6 Intro

Spreadsheets are the ultimate everyday programming tool. We will teach them how cells connect, and the crucial concept of locking cells with dollar signs.

Press Down to discuss relative vs. absolute references.

Formulas & Cell Referencing

Relative vs. Absolute

  • Relative (`A1`): When copied or dragged, the reference shifts relative to the direction.
  • Absolute (`$A$1`): Dollar signs lock the cell. It will never change when copied. Used for fixed rates/goals.

Core Functions

  • `SUM(range)`: Adds values.
  • `IF(logical_test, true_val, false_val)`: Basic decision maker.
  • `XLOOKUP(search, range, return_range)`: Searches a grid for a matching row value.

Teaching Points

The Magic Calculator Analogy: Traditional calculators are static. If you change a number, you recalculate the total. A spreadsheet is a living network. If cell A1 changes, everything referencing A1 updates immediately.

Locking explanation: If tax rate is in Z1 (5%), and you calculate tax for 10 items in column A. If you write =A1*Z1 and drag down, it shifts to =A2*Z2 (Z2 is blank!). You must write =A1*$Z$1 to lock the tax cell.

Lab: The Teen Budget Tracker

Project Time

Build a two-tab budget tracker in Google Sheets or Excel:

Tab 1: Transactions

Log transactions with: Date, Category (Income, Food, Games, Clothes, Savings), Description, and Amount.

Tab 2: Dashboard

Automate with formulas:
• `=SUMIF(Category, "Income", Amount)`
• `=IF(SavingsRate >= $B$1, "Goal Met!", "Keep Saving!")`
Add a pie chart showing expenses.

Lab Guidance

Open Google Sheets with them. Show them how to rename tabs at the bottom. Enforce no manual typing of totals. Everything must use formulas!

Let them add a transaction and witness the dashboard update automatically.

Lesson 6 Check-In

Questions

  1. What character must every spreadsheet formula begin with?
  2. If cell B5 contains `=A5` and you drag/copy B5 down into B6, what does B6 become?
  3. How do you lock cell D3 in a formula so it never shifts when copied?

Quiz Answers

  1. The equals sign (=).
  2. =A6 (relative reference shifts down).
  3. Write it with dollar signs: $D$3.

Lesson 7

Cybersecurity & Digital Hygiene

Securing Your Digital Life: Passwords, Phishing, and Privacy

Key Objectives

  • Understand password entropy (length beats complexity).
  • Learn multi-factor authentication (MFA) methods and risks.
  • Identify phishing indicators and social engineering tactics.

Lesson 7 Intro

Today is a critical safety lesson. Teens are targets for account hijacking. We'll look at password entropy math and how social engineering bypasses tech blocks.

Press Down to explain passwords and MFA.

Entropy, MFA, & E2EE

Password Entropy

Entropy measures randomness. Length is far more secure than complexity. A passphrase like `apple-window-shoe-yellow` is vastly harder for a script to brute-force than `P@$$w0rd!`.

MFA & Encryption

MFA: Combines factors (something you know + have + are). SMS codes can be hijacked (SIM swap); app authenticators are safer. E2EE: Scrambled on device, keys only held by sender/receiver.

Castle Analogy (Script)

Explain: "Your password is the key to a castle. If you choose Dragon123, a thief standing outside can guess it in seconds. A long passphrase is like a complex combination lock."

"But what if the thief dresses as a castle guard and says 'Verify your identity by whispering the key through the keyhole'? If you give it to them, password strength doesn't save you. That is phishing. To block this, we add a second lock: a finger scanner or a physical dial you carry (MFA)."

Lab: The Security Audit

Challenge

Analyze the three client profiles in the lesson guide. Identify security leaks and write a fix plan:

Leo (Gamer)

Reuse of `LeoGamer2011` for all accounts. No 2FA. Clicked a Discord DM link for a free Steam game.

Sophia (Creator)

Random 16-character passwords with SMS 2FA. Posts daily public vlogs tagging her precise coffee shop location and home door.

Mr. Davis (Dad's Friend)

Got text from "Netflix-support" at `netflix-billing-update.net`. Typed password & credit card details.

Lab Guidance

Read the details from `lesson_07_cybersecurity_hygiene.md`. Let them dissect each case:

  • Leo: Credential stuffing risk. If one site gets hacked, hackers get all his accounts. Discord DM was a credential phishing attack. He should change passwords and install an authenticator.
  • Sophia: Account security is good, but physical privacy is leaked. Strangers can figure out her school, home, and daily routine. She should hide school logos and turn off precise geotagging.
  • Mr. Davis: Classic SMS phishing (Smishing). Urgency trick. He must call his bank immediately, change his password, and review card charges.

Lesson 7 Check-In

Questions

  1. Which password is harder to crack: `Pa$$w0rd123!` or `apple-window-shoe-yellow`?
  2. What are the 3 factors of authentication?
  3. What does End-to-End Encryption (E2EE) prevent?

Quiz Answers

  1. apple-window-shoe-yellow: Length increases combinations exponentially. Short passwords with complexity are guessed quickly by modern cracking software.
  2. Something you know (password), something you have (phone/key), and something you are (fingerprint/face).
  3. Prevents intermediaries (ISPs, hackers on Wi-Fi, or the service provider itself) from reading message content.

Lesson 8

Mobile & Platforms

Under the Screen: Permissions, Privacy, and App Ecosystems

Key Objectives

  • Compare native applications with web applications.
  • Understand the OS sandboxing model.
  • Learn how app tracking and Advertising IDs function.

Lesson 8 Intro

This is a highly practical lesson that deals with their own phones. They will audit what permissions their apps have in the background.

Press Down to explain sandboxing and permissions.

Sandboxes & Tracking

OS Sandboxing

Apps run inside an isolated **sandbox**. They cannot read other apps' data, photos, or location unless the OS prompts the user. This keeps malicious apps isolated.

Targeted Advertising

Free apps make money by tracking. They use your Advertising ID (IDFA on iOS) to link your behavior across different apps and sell user profiles to brokers.

Hotel Analogy (Script)

Explain: "Your phone is like a highly secure hotel. You are the owner. An app is a guest checking in."

"In the old days, guests got master keycards. They could look in your drawers (photos) and read your diary (contacts). In mobile sandbox hotels, guests are locked in their own rooms. If they want to use the camera, the front desk (OS) calls you and asks for permission."

Ask: "Why does a calculator app want location permission?" (To track you and sell ads. Denying it won't break the calculator!).

Lab: Smartphone Privacy Audit

Activity

Get your smartphone. Navigate through settings to audit permissions:

1. Location & Camera

Find apps with "Always Allow" location access. Switch to "While Using" or "Never." Turn off **"Precise Location"** for apps that don't need it. Check camera permissions.

2. Tracking & Background

Turn off **"Allow Apps to Request to Track"** (iOS) or **"Delete Advertising ID"** (Android). Turn off **Background App Refresh** for non-essential apps to save battery.

Lab Guidance

Let the kids audit their own phones. Direct them using the navigation paths in the lesson guide.

Discuss the results: How many apps had camera access? What did they change? They will be surprised by how much battery and data background app refresh consumes.

Lesson 8 Check-In

Questions

  1. What is the difference between a Native App and a Web App?
  2. What does a mobile operating system "sandbox" do?
  3. What is an Advertising ID?

Quiz Answers

  1. Native App: Downloaded, runs directly on hardware with deep API access. Web App: Runs inside browser sandbox, restricted hardware access.
  2. Isolates apps so they cannot access system files or other apps' data without user approval.
  3. A unique identifier code on your phone used by advertisers to track your activity across different apps to build a profile.

Lesson 9

AI as a Bicycle for the Mind

How Large Language Models Work, Prompting, and the Art of Fact-Checking

Key Objectives

  • Understand LLMs as autocomplete systems, not conscious minds.
  • Learn why AIs hallucinate (making up convincing details).
  • Master prompt engineering guidelines and rigorous verification.

Lesson 9 Intro

AI is everywhere. But teens often treat it as a search engine or source of truth. We will teach them that LLMs are word-prediction systems, and how to verify their output.

Press Down to explain probability and tokenization.

Probability & Prompting

Predictors & Tokens

LLMs break text into numerical fragments called tokens. They look at your prompt and calculate the mathematical probability of the next token. They don't know "facts," only word patterns.

Prompt Engineering

Improve AI output by defining a **Role** (e.g. "Act as a math teacher"), setting clear **Constraints** (e.g. "Do not use jargon"), and asking it to **think step-by-step**.

Autocomplete Analogy (Script)

Explain: "When you text 'I am going to the...', your phone suggests words. It looks at your past typing and what millions of others wrote. LLMs do this on a massive scale."

"But does your phone's autocomplete know where you are actually going? No. It's just guessing. That's why AIs make things up. Confidently guessing a wrong word is called a **hallucination**."

Lab: Fact-Check the Machine

Challenge

Part 1: The Trap

Ask an LLM to write a biography of "Sir Reginald Vance, inventor of the steam typewriter." Notice how confidently it creates fake dates and details.

Part 2: The Audit

Ask the LLM to summarize the 1858 transatlantic cable project. Fact-check every name, date, and ship. Highlight correct facts in green, and errors in red.

Lab Guidance

Provide them with access to Gemini, ChatGPT, or Claude. Let them see the hallucination in Part 1. Explain: because the prompt assumed the inventor was real, the AI predicted words matching a biography template.

In Part 2, let them research on Wikipedia or Google. Highlight that AI is a helper, but humans must remain the verification layer.

Lesson 9 Check-In

Questions

  1. How does an LLM decide what word to write next?
  2. What is an AI "hallucination"?
  3. Why does asking an AI to "think step-by-step" make it better at math and logic?

Quiz Answers

  1. By calculating the mathematical probability of the next word/token based on its training patterns.
  2. When the AI model generates an answer that sounds confident and realistic but is factually false or made up.
  3. It forces the model to generate the intermediate calculation tokens first, building a logical pathway to the answer rather than trying to guess the final number immediately.

Lesson 10

Tech Troubleshooting

The Diagnostic Loop: How to Fix Anything with Science

Key Objectives

  • Learn the scientific troubleshooting loop.
  • Master isolation of variables (changing one thing at a time).
  • Use diagnostic tools to fix real network and system errors.

Lesson 10 Intro

This is the final exam! We will teach them the troubleshooting mindset, and then let them loose on a "broken" computer that you set up beforehand.

Press Down to explain isolation of variables.

The Diagnostic Loop

The Diagnostic Loop

  1. Symptom: Define exactly what is failing (read error codes!).
  2. Scope: Isolate scope (one site or all? this device or all?).
  3. Hypothesis: Formulate a testable guess of the root cause.
  4. Test: Change **one variable** at a time. Check if symptom resolves.
  5. Document: Understand the fix to build experience.

Light Bulb Analogy (Script)

Explain: "You walk in your bedroom, flip the switch, and it stays dark. What do you do?"

  • If the hallway light is ON, house power is fine.
  • If you put the bulb in a working lamp and it lights up, the bulb is fine.
  • Therefore, the bedroom switch or wiring is broken.
  • If you immediately ran to the basement and flipped the main house breaker, you changed the wrong variable! That is bad troubleshooting.

Lab: The "Broken PC" Exam

Final Exam

The parent has disabled a few settings on this PC. You must diagnose and fix them using built-in system tools:

Glitch 1

Wi-Fi icon is missing or disabled. Diagnose using Device Manager network adapters.

Glitch 2

Wi-Fi is connected, but websites fail to load. Ping `8.8.8.8` (works) vs `google.com` (fails). Fix in **DNS settings**.

Glitch 3

Browser loads sites, but fonts are Comic Sans or layout is upside down. Find the hidden **Extension Manager** setting.

Final Exam Setup Guidance

Refer to `lesson_10_troubleshooting_lab.md` to configure the glitches before they start. Let them work together. Avoid giving them the answer immediately. Encourage them to use command line tools like ping and check error codes.

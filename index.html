Lesson 1

Under the Hood

Hardware vs. Software: How Computers Actually Think

Key Objectives

  • Identify and define the core hardware components of a PC.
  • Understand the flow of data: Input, Processing, Storage, and Output.
  • Learn how specs (GHz, cores, cache, volatile memory) dictate speed.

Press to enter the lesson.

Lesson 1: Introduction

Introduce the subject. Explain that computers aren't magic boxes; they are composed of physical devices performing basic electrical operations rapidly.

Go down to discuss the general architecture.

System Architecture Flow

How a computer interacts with the outside world

1. Input & Output

• **Inputs:** Keyboards, mice, cameras, sensors converting actions to binary bits.
• **Outputs:** Screens, speakers, printers converting bits back into visual/audio forms.

2. Processing & Storage

• **Processing:** The CPU running electrical gates to execute software instructions.
• **Storage:** Holding data when active (RAM) and saving it long-term (SSD/HDD).

Socratic Prompt

Ask: "When you move your mouse, how does the computer know where to draw the cursor?"

Explain: The mouse coordinates are inputs (e.g. Move +10 X, -5 Y). The processor calculates the new coordinates, and sends instructions to the display adapter (output) to illuminate different pixels.

The CPU (Central Processing Unit)

The brain that executes the instructions

Clock Speed

Measured in Gigahertz (GHz). Represents processing cycles per second. A 4.0 GHz CPU performs 4 billion cycles per second.

Core Counts

Separate physical processing units. Single-core is 1 worker; multi-core (8, 12, 16) allows running multiple tasks concurrently.

CPU Cache

Ultra-fast memory built directly on the CPU chip (L1, L2, L3). Holds the next immediate instructions, saving trips to RAM.

The Chef Analogy

The Chef is the CPU.

  • GHz Clock speed: How fast the chef can chop or stir. (4 billion movements per second).
  • Cores: How many arms or helper chefs there are. An 8-core CPU is like an 8-armed chef who can do 8 recipes at once.
  • Cache: A small spice rack right above the chef's head. Holds the ingredients they need right this second so they don't have to turn around.

RAM (Random Access Memory)

The computer's temporary active workspace

Speed & Capacity

• **Speeds:** Measured in MegaTransfers (e.g. DDR5 5600 MT/s). Faster speeds feed the CPU data quicker.
• **Capacity:** Measured in Gigabytes (GB). 8GB is basic; 16GB is gaming standard; 32GB+ is multitasking powerhouse.

Volatility

• **Active workspace:** When you boot Windows or open Discord, the files are loaded from storage into RAM.
• **Volatile:** Requires constant power. If power cuts off, the electrical charges drain and all RAM data vanishes instantly.

The Countertop Analogy

RAM is the Kitchen Countertop.

  • When the chef is making cookies, they lay out flour, sugar, and baking sheets on the counter because it's fast to grab.
  • If the counter is too small, they run out of space and have to pack ingredients back into the pantry, slowing down cooking.
  • At night, the kitchen closes and the counter is wiped completely clean (Volatile).

SSD vs. HDD (Storage)

Where files live when the power is off

Specification HDD (Hard Disk Drive) SSD (Solid State Drive)
Technology Spinning magnetic platters & moving read-heads. NAND Flash microchips (no moving parts).
Speed Slower (~100-150 MB/s). High seek latency. Fast (~3,500-7,000 MB/s for PCIe NVMe).
Durability Fragile. Dropping it can damage platters. High. Shockproof, silent, uses less power.
Use Case Cheap bulk storage (backups, archival data). OS drive, games, applications, active files.

Pantry Analogy

Storage is the Pantry. Holds cookbooks and flour long-term. Retains data without power (Non-volatile).

  • HDD: A pantry at the end of a long, dark hallway. The chef has to walk down the hall, turn a physical dial to open the door, and search. Takes time (latency).
  • SSD: A modern drawer organizer right under the counter. The chef pulls it open and grabs the spice instantly.

Motherboard & Power Delivery

The Motherboard

The central circuit board that houses the CPU and connects all hardware.
• **Sockets:** Physical interfaces (e.g. AM5, LGA1700) matching specific CPUs.
• **PCIe Slots:** High-speed expansion channels for GPUs and NVMe SSDs.
• **Bus lines:** Trace lines that route binary signals between components.

The PSU & Cooling

• **Power Supply (PSU):** Converts high voltage AC wall current into low voltage DC power (12V, 5V, 3.3V) needed by components.
• **Thermal Management:** Processors do math by moving electrical current through gates, generating heat. Heatsinks, fans, and liquid coolers dissipate heat to prevent thermal throttling.

Key Points

Motherboard is the floor/wiring: Connects the pantry, countertops, and chef. If a bus lane is damaged, components can't communicate.

PSU is the power plug: High voltage AC is dangerous; the PSU regulates it. A bad PSU can fry all other components.

Cooling: If a CPU gets too hot, it slows down its clock cycles to protect itself from melting. This is called thermal throttling.

The GPU (Graphics Processing Unit)

Serial vs. Parallel Processing

CPU: Sequential

Designed with a few powerful cores (4 to 16) optimized for **serial processing** (running one complex instruction set after another very fast).

GPU: Parallel

Designed with thousands of small, specialized cores optimized for **parallel processing** (doing millions of simple math operations, like calculating pixel colors or AI vectors, all at once).

**VRAM (Video RAM):** Dedicated high-speed memory on the graphics card holding textures and frame data for immediate GPU rendering.

Assistant Chef Analogy

If the head chef (CPU) had to decorate 2 million tiny cakes (pixels on a screen) at the same time, they couldn't serve any main courses. So they hire a specialized pastry helper (the GPU) with 2,000 tiny hands to decorate the cakes in parallel.

Ask: "Why do AI programs run on GPUs instead of CPUs?" (AI model math is composed of massive matrix multiplications—millions of simple addition/multiplication steps that can be run in parallel much faster on a GPU).

Lesson 1 Discussion

Socratic Scenarios

  1. You buy a game. Your CPU and GPU are very fast, but your computer only has 4GB of RAM. The game recommends 16GB. What will the gameplay feel like, and why?
  2. A laptop advertisement says: "1TB HDD! Core i7 CPU! Ultra-fast!" What is the hidden trap in this specification?

Discussion Guidelines

  1. RAM Bottleneck: The game will stutter heavily. The CPU will have to constantly write temporary game files back to the slow storage drive (HDD/SSD) and wait for them to load because there's not enough room on the RAM countertop. This is called disk swapping or thrashing.
  2. The slow HDD trap: Even though the CPU (i7) is very fast, booting the computer and opening programs will feel sluggish because the HDD is slow at loading files. The CPU will spend most of its time waiting for the spinning disk platters to fetch data. Adding a cheap SSD would make the machine feel 10x faster.

Lesson 2

Files, Folders & The Cloud

Managing Data Locally and Globally

Key Objectives

  • Understand file headers, extensions, and directory paths.
  • Learn to manipulate directories using the Command Line Interface (CLI).
  • Explain virtualization, server nodes, and the physical footprint of the cloud.

Lesson 2 Intro

We take file systems for granted in visual interfaces. In this lesson, we explore how data is organized, how directories form branches, and how we interact with them via code (CLI) and in cloud server nodes.

Press Down to learn about extensions and headers.

File Formats & Headers

How computers identify data types

1. The File Header

The first few bytes of any file contain a hidden code (the **magic number** or header). For example, a PNG file always starts with the bytes `89 50 4E 47`. The OS reads this header to confirm the file type regardless of its name.

2. File Decoders

• **Binary files** (like `.exe`, `.png`, `.mp3`) store data in packed machine bytes. They require specific decoders to open.
• **Text files** (like `.txt`, `.csv`, `.py`) store raw characters encoded in ASCII or UTF-8 and can be read by any text editor.

Explanation

Explain that file extensions (.jpg, .mp4) are labels for the OS, but the true file identity is written in its header bytes. If you delete the extension, the file is still intact, but the OS won't know which program to assign it to until it scans the header.

Directory Trees & Paths

Mapping locations on storage devices

Absolute Paths

The full address starting from the drive root.
• **Windows:** `C:\Apps\SummerAcademy\curriculum\comp101\lesson_01.md`
• **Linux/macOS:** `/var/www/index.html`

Relative Paths

The address relative to your **current working directory** (Cwd).
• If you are currently in `C:\Apps\SummerAcademy\`, the relative path is:
`curriculum\comp101\lesson_01.md`

**Folder Hierarchy:** Root directories branch into parent folders, which contain child subfolders and terminal files.

Pathing Metaphor

Absolute path is a GPS coordinate or mailing address (e.g. 1600 Pennsylvania Ave, Washington DC). It works from anywhere.

Relative path is a direction from where you are (e.g. "turn left, go down two blocks, third house"). It only works if you are in the correct starting spot.

The Command Line (CLI)

Talking to the operating system using code

GUI vs. CLI

• **GUI (Graphical User Interface):** Point and click with a mouse. Slow for batch tasks.
• **CLI (Command Line Interface):** Typing text instructions. Fast, automatable, and essential for servers.

Essential Shell Commands

  • `cd `: Change directory (move to folder).
  • `ls` or `dir`: List files in the current folder.
  • `mkdir `: Make a new directory folder.
  • `mv `: Move/Rename a file.

CLI Introduction

Explain that before screens had mouse cursors (pre-1980s), the CLI was the only way to use a computer. Developers and network administrators still use it because typing commands is much faster than clicking through 10 folders.

Show them the dot notation: . means current directory; .. means parent directory. (e.g. cd .. moves up one level).

The Cloud: Virtualization

How servers are split into virtual pieces

Physical Nodes

Data centers contain rows of physical server units (nodes). These are massive racks of CPUs, RAM, and hard drives, but buying a physical server for every user is expensive and wasteful.

The Hypervisor

A virtualization software layer that splits a physical server's resources. It hosts multiple independent **Virtual Machines (VMs)**, sharing the same physical CPU/RAM securely.

Virtualization Analogy

Explain virtualization like an apartment building. Instead of building 50 single houses (physical servers) for 50 people, you build one large apartment complex (physical hardware) and partition it into 50 rooms (VMs). Each tenant has their own door and keys, but they share the same physical foundation and plumbing.

Data Centers Under the Hood

The physical infrastructure of the internet

HVAC Cooling

Thousands of processors create massive heat. Giant chiller units and airflow vents run continuously to prevent hardware failures.

Redundant Power

To prevent data loss, facilities have banks of batteries (UPS) and diesel generators that start in milliseconds if the grid fails.

Data Security

Biometric access controls, perimeter cages, and hard drive shredders to destroy decommissioned data.

Datacenter Realities

Explain that data centers consume huge amounts of green energy. Tech companies locate data centers in cold climates (like Iceland or Sweden) to reduce electricity bills by using cold air from outside for natural cooling.

Discussion & Datacenter Math

Discussion

If a file deleted from your Recycle Bin on your local computer is gone, why is a photo deleted from Instagram sometimes still accessible?

Fermi Math Recall

If a 50,000-server data center draws 25 MW of electricity at any second, and a family home uses 1.2 kW, how many houses' worth of power does the data center consume?

Formula: $25,000,000 \text{ Watts} \div 1,200 \text{ Watts}$

Answers

  1. Cloud redundancy: When you upload to the cloud, files are duplicated across multiple geographic servers (data replication) to prevent loss if a hard drive crashes. Deleting a photo sends a deletion request, but caches and index tables take time to clean up, or the company keeps archival records.
  2. Fermi Math Answer: ~20,833 homes. A medium-sized town's worth of power is spent just for one datacenter!

Lesson 3

How the Internet Works

Packets, DNS, and the Global Network Pipeline

Key Objectives

  • Analyze packet switching and TCP/IP reliability protocols.
  • Understand the DNS hierarchy and caching mechanisms.
  • Trace network packets jumping between routers around the globe.

Lesson 3 Intro

In this lesson, we demystify the network layers. How does a request leave our home router and return files from servers across the world in milliseconds?

Press Down to explain packet switching.

Packet Switching & TCP/IP

Slicing data for transmission

Packet Fragmentation

Files are broken into **packets** (usually ~1500 bytes). Each packet gets a header detailing:
• Source IP address.
• Destination IP address.
• Sequence number (e.g. "Packet 4 of 100").

TCP/IP Protocol

• **IP (Internet Protocol):** Directs the packets to the correct numeric address.
• **TCP (Transmission Control Protocol):** Guarantees delivery. It tracks sequence numbers, checks for corruption (checksums), and requests retransmission of lost packets.

Postcard Metaphor (Script)

Explain: "Tear a 100-page notebook into 100 pages. Mail each page as a separate postcard to Tokyo. Each postcard travels in different trucks/planes. When your friend receives them, they reassemble them by page numbers."

If postcard 45 is lost, your friend sends a card back: "Send page 45 again." That is TCP/IP reliability.

DNS: The Internet Phonebook

Translating names to numbers

DNS Hierarchy

When you type `google.com`, your browser asks:
1. **Local Cache:** Checked first.
2. **Recursive Resolver:** Queries root servers (`.`), Top-Level Domain (TLD) servers (`.com`), and finally the **Authoritative Nameserver** for `google.com` to fetch the IP.

DNS Cache

To prevent millions of duplicate queries, computers and routers save (cache) lookup results for a specific period (TTL - Time to Live).

DNS Plumbing Details

Explain DNS like a lookup system. Root servers point resolver to .com servers. The .com server points to Google's name server, which returns the IP address 142.250.190.46.

Ask: "What happens if a company changes their server IP but visitors still get the old IP?" (Their local cache is still holding the old record until the Time To Live expires).

IP Routing & Global Cables

The physical pathway of network packets

Routers & Hops

Routers are nodes that forward data packets between networks. Each router transition is a **hop**. Routers use protocols (like BGP) to dynamically select the fastest available path.

Undersea Fiber Cables

Packets don't travel through space to cross oceans. Over 95% of international traffic runs through fiber optic submarine cables laid on the seabed, carrying pulses of light.

Undersea Infrastructure

Show them that packets physically travel. To access a European server, your data goes to a local hub, travels down a fiber cable on the seabed of the Atlantic Ocean, enters a coastal routing station, and arrives at its destination in less than 100 milliseconds.

Client-Server & HTTP

How programs communicate

HTTP Request

Your browser (Client) sends a request header to a server:
GET /index.html HTTP/1.1
Host: google.com

HTTP Response

The server returns data and a **status code**:
• **200 OK:** Request succeeded.
• **404 Not Found:** File doesn't exist.
• **500 Internal Server Error:** Server crashed.

Web Protocol

Explain that HTTP is just a standard language for requests. Status codes tell the browser how to behave. 404 means the path is wrong; 500 means the server had a code glitch.

Lesson 3 Discussion

Socratic Scenarios

  1. When you load a website, the images load one by one, sometimes appearing out of order. Why does this happen based on packet switching?
  2. A construction backhoe accidentally cuts a fiber cable underground in your city. Why doesn't the entire city's internet go down?

Discussion Guidelines

  1. Out of order packets: Images are composed of thousands of packets. Since packets travel different routing pathways dynamically, some arrive faster than others. The browser displays whatever packets it has assembled first, or waits until all are reordered.
  2. Routing Redundancy: The internet is a mesh network. If one fiber path is severed, local routers instantly detect the link failure and reroute packets through other connections, keeping traffic flowing (though possibly slightly slower).

Lesson 4

Collaboration Evolution

The History of Work: Local to Collaborative

Key Objectives

  • Trace the transition from floppy-disk office suites to cloud databases.
  • Explain conflict resolution algorithms: OT vs. CRDT.
  • Understand the concept of version control and git repositories.

Lesson 4 Intro

How we work has evolved dramatically. Today, we look at the software architecture of collaboration—how Google Docs keeps cursors synced and how programmers use Git to edit code together.

Press Down to explain the Desktop Era.

The Desktop Era

Local locks and versioning friction

Local File Locking

In early Microsoft Office days, when a file was opened from a local shared folder, the OS locked it as **Read-Only** for other users. Only one person could edit at a time.

Attachment Chaos

To collaborate, users emailed files. If three managers edited the attachment separately, the creator had to copy-paste the edits back into a master copy, resulting in:
report_final_v2_edit_JD.docx

History Context

Explain how floppy disks were physically run across offices to share files. This was called Sneakernet. Collaboration was slow and versioning was error-prone.

Under the Cloud: Syncing

How databases keep screens identical

Operational Transformation (OT)

Used by Google Docs. A central server acts as a referee. When two edits arrive at the same index simultaneously, the server shifts one edit to the right so both appear correctly.

CRDTs

Conflict-free Replicated Data Types. Used in Apple Notes/Figma. Every character has a unique ID. Edits can be merged mathematically in any order without a central server referee.

Tech Explanation

If you and a friend edit a document at the same time: You type "A" at index 5. Your friend types "B" at index 5. Without OT, whichever request arrives second overwrites the first. With OT, the server transforms the second index: You get "AB" or "BA" and both characters appear.

Version Control (Git)

Collaboration systems for programmers

Commits & History

Git doesn't overwrite files; it tracks **snapshots** (commits) of code changes. A programmer commits code with a message explaining what changed. You can roll back to any commit in history.

Branches & Merging

Developers copy code onto a **branch** to work on a feature. When finished, they **merge** their branch back to the master branch. Conflicts are resolved line-by-line.

Programming Collaboration

Explain that Git is the foundation of the modern software industry. Without Git, hundreds of developers could not write code on the same software simultaneously.

Lesson 4 Discussion

Socratic Scenarios

  1. You edit a shared cloud document while offline on a plane. A teammate edits the same document online. When your laptop reconnects, how does the system merge the changes?
  2. Why is a Git history (which lists every change ever made) safer than just saving over the same file daily?

Discussion Guidelines

  1. Offline Merge: The system will try to sync. If you edited different paragraphs, the server will append both. If you edited the exact same line, it triggers a "merge conflict" and asks you to select which version to save.
  2. Safe rollback: If a developer writes a bug that breaks the app, they can simply search the commit history, identify the exact commit that broke the code, and restore the previous working snapshot in one command.

Lesson 5

Visual Communication

Document Design & Presentations: Typography, Hierarchy, and Whitespace

Key Objectives

  • Identify Serif vs. Sans-Serif fonts and spacing metrics.
  • Master visual hierarchy: heading scale and F-shaped reading layouts.
  • Contrast slide presentation layouts (Billboard Test) with written briefs.

Lesson 5 Intro

Design is not decoration; design is communication logic. Today we study how to layout documents and slides to direct attention and reduce cognitive load.

Press Down to study typography.

Typography & Readability

Serif vs. Sans-Serif fonts

Georgia / Serif

Have small feet (serifs) at the ends of letters.
• **Best for:** Long printed books, newspapers, and print layout. The serifs guide the eye along lines of text.

Arial / Sans-Serif

Flat, clean letters without feet (sans).
• **Best for:** High-resolution digital screens, presentation titles, and minimal interface layouts.

**Line Spacing (Leading):** Text lines should have ~1.4 to 1.5 line-height. Too tight or too loose exhausts the reader's brain.

Typography Rule

Enforce the Rule of Two: use one Sans-serif font for headers (bold, punchy) and one Serif or readable Sans-serif for body text. Never use decorative fonts (like Comic Sans or papyrus) for professional documents.

Layout & Visual Hierarchy

Directing the eye of the reader

The F-Pattern

Digital readers do not read word-by-word. They scan in an **F-shape**: across the top header, down the left margin, across the first subheading, and down. Use headings to capture scanning eyes.

Visual Contrast

Direct attention by scaling element size (e.g. Title 32px vs. Body 14px) and weight (Bold vs Light). The most important item must be visually distinct.

Visual Hierarchy

If everything is bold, nothing is bold. Hierarchy is about contrast. If you want a key number to stand out, make it huge and put it next to simple text.

The Power of Whitespace

Giving content room to breathe

Negative Space

Whitespace (empty space around layout cards or margins) is not wasted space. It isolates components, groups related items, and prevents visual clutter.

Cognitive Overload

When a page is packed with dense paragraphs, different colors, and icons, the viewer's brain experiences overload. They lose focus and stop reading.

Whitespace Discussion

Look at Google's homepage. It is mostly blank whitespace with a single search bar in the center. Compare it to Yahoo in the 2000s (hundreds of links, ads, news items). Google succeeded partly because its interface had almost zero cognitive load.

Slide Deck vs. Written Brief

Choose the correct format for the context

Format Type Written Brief (Document) Presentation (Slide Deck)
Purpose To be read independently by individuals. To support a live speaker presenting ideas.
Text Density High. Full sentences, details, tables. Low. Max 15 words per slide. Billboards.
Role of Speaker Not present (file stands alone). Critical (slides are incomplete without speaker).
Structure Headings, paragraphs, index. Visuals, massive numbers, key statements.

Slide Rule

Remind them of the **Billboard Test**. Slides are visual anchors. If you read your slides word-for-word, the presentation is a failure. You could have just emailed them a document.

Lesson 5 Discussion

Socratic Scenarios

  1. You are presenting to your class. You put a slide on screen with 8 lines of text and start reading it. What is your class actually doing?
  2. Why do newspapers print text in narrow columns rather than stretching the sentences across the entire page?

Discussion Guidelines

  1. Split Attention: The class is reading the slide faster than you can speak it. Since they are reading, they stop listening to your voice. They get bored because your speech is redundant.
  2. Optimal Line Length: If a line of text is too wide (more than 70-80 characters), the reader's eye has trouble finding the start of the next line when scanning back to the left margin. Narrow columns make scanning fast and effortless.

Spreadsheets are the software tool that run modern business. Understanding how data grids operate and how formulas recalculate dynamically is the first step of coding.

Spreadsheet Data Architecture

Grids of columns and rows

Cells & Coordinates

Every box in a sheet has a coordinate based on its Column letter and Row number (e.g. `B4`). Cells contain different **Data Types**: Text strings, numeric integers, currencies, dates, or boolean logical flags.

Records & Fields

To build clean data tables:
• **Columns (Fields):** represent attributes of the data (e.g., Date, Category, Price).
• **Rows (Records):** represent a single transaction item. Never merge cells inside data lists.

Grid Logic

Explain that spreadsheets are just databases with a visual interface. Keeping your columns consistent (e.g., only putting numbers in the "Amount" column) is essential for formulas to work.

Locking Cells: Relative vs. Absolute

Relative offsets vs. fixed coordinates

`A1` : Relative

Points to a cell relative to the formula's position. If cell `B1` has `=A1` and you copy/drag B1 down into `B2`, the formula shifts dynamically to `=A2`.

`$A$1` : Absolute

The dollar signs lock the reference. If you write `=$A$1` in `B1` and drag it down into `B2`, the reference remains fixed to `A1`. Used for constant rates.

*Shortcut:* Press **F4** while editing a formula in Excel/Sheets to toggle dollar signs automatically.

F4 locking

Emphasize this slide. Absolute vs. Relative is the biggest stumbling block for spreadsheet beginners. If they don't lock cells, copying formulas down will result in shifting calculations and incorrect results.

Aggregation Functions

Processing lists of numbers

Standard Functions

  • =SUM(D2:D100): Adds all numbers in range.
  • =AVERAGE(D2:D100): Returns mean of range.
  • =COUNT(D2:D100): Counts numeric entries.

Conditional Aggregations

  • =SUMIF(B2:B100, "Food", D2:D100): Sums D values only if corresponding B cell is "Food".
  • =COUNTIF(B2:B100, ">50"): Counts cells higher than 50.

Conditional Math

Show them that SUMIF combines a filter step with an addition step. This is useful for budget dashboards where you want to sum categories automatically.

Conditionals: `IF` statements

Making calculations make decisions

=IF(logical_test, value_if_true, value_if_false)

Evaluates a condition and returns different values depending on the result.

• **Basic IF:** =IF(B7 >= 0.20, "Goal Met!", "Save More!")
• **Nested IF:** =IF(A1 > 90, "Grade A", IF(A1 > 80, "Grade B", "Grade C"))

Logical Branching

Explain that IF functions work like road forks. The computer checks if the statement is true and routes the cell output accordingly. This is basic logical programming.

Lookup Functions: `XLOOKUP`

Connecting tables of data

=XLOOKUP(search_value, lookup_array, return_array)

Searches a column for a target item and returns the value on the same row in another column.

• **Example:** You have a product barcode in cell `A2`. You want to find its price in a separate catalog table (Barcode in `Y:Y`, Price in `Z:Z`):
=XLOOKUP(A2, Y:Y, Z:Z)

Data Linking

Lookup functions allow you to relate tables together. Instead of copy-pasting prices or customer names into every single transaction row, you just write a lookup formula that fetches details from a master catalog table automatically.

Lesson 7 Intro

Cybersecurity is about defense. We look at the mathematics of passwords, the weak links in authentication (like SMS), and how social engineering bypasses tech walls.

Press Down to study entropy math.

The Math of Passwords

Entropy and search combinations

Brute-Force Math

If a password has length $L$ and character set size $C$, the combinations are $C^L$.
• Adding 1 character increases combinations **exponentially** ($C^{L+1}$).
• Adding symbols only increases character set size **linearly** ($C+10$).

Passphrases beat Complexity

• `P@$$w0rd1!` has symbols, but is short (10 chars) and human-patterned. Cracked in minutes.
• `apple-window-shoe-yellow` is long (26 chars), random, and has massive entropy. Takes trillions of years to brute-force.

Entropy Explanation

Explain that cracking programs don't guess one character at a time. They run dictionary attacks and pattern guessing. Length is the ultimate defense. A passphrase made of 4 simple random words is easier to remember for you, but virtually impossible for a computer to guess.

The MFA Spectrum

Something you Know, Have, and Are

1. SMS MFA (Weak)

Codes texted to your phone. Vulnerable to **SIM Swapping** (hackers tricking carrier to move your number to their SIM).

2. App MFA (Strong)

Authenticator apps (Google/Bitwarden) generate time-based codes locally (TOTP). No network transmission required.

3. Passkeys (Ideal)

Uses cryptography (FIDO2) linked to device biometrics. Immune to phishing because keys only match the real domain name.

MFA Comparison

Explain that SMS MFA is better than nothing, but SIM Swapping has allowed hackers to compromise high-profile accounts. App MFA is local, making it immune to SIM swaps. Passkeys are the future because they bind directly to the web address (cannot be phished).

Phishing & Social Engineering

Bypassing security by tricking humans

Social Engineering

Manipulating psychological triggers:
• **Urgency:** "Act within 24 hours!"
• **Authority:** "Official Netflix Support."
• **Fear:** "Your banking account is locked."

Verification Checklist

• **Check Sender Domain:** Is it `netflix.com` or `netflix-billing-support.net`?
• **Hover check:** Hover over links before clicking to check their destination URL.
• **Never share codes:** Support will never ask for your 2FA code.

Phishing Scenarios

Remind them that hackers don't always look for code bugs to break in. They look for human vulnerabilities because tricking a person into typing their password is much easier.

End-to-End Encryption (E2EE)

Symmetric vs. Asymmetric cryptography

Symmetric Cryptography

Uses the **same key** to encrypt and decrypt the message. Both parties must share this secret key safely. If intercepted in transit, the lock is broken.

Asymmetric Cryptography

Uses two keys: a public key (anyone can lock) and a private key (only you can unlock). E2EE tools (WhatsApp/Signal) encrypt messages with the receiver's public key, ensuring only their private key can decrypt them.

E2EE Analogy

Imagine your friend sends you a padlock (Public Key). Anyone can click the lock closed. Your friend keeps the physical key (Private Key). You put a letter in a box, close the padlock, and mail it. Even if the mail carrier intercepts it, they can't open it because only your friend holds the key.

Trackers & Privacy

How companies watch your moves

Cookies

Small text files saved in your browser by websites. First-party cookies remember logins; third-party cookies track you across sites.

Device Fingerprinting

Combining browser version, OS, screen size, and plugins to create a unique ID to identify your machine without cookies.

Data Brokers

Companies that buy and compile data from apps, retail cards, and web histories to sell profiles to advertisers.

Privacy Issues

Explain that tracking is how the free internet is funded, but it has created a massive surveillance industry. Using ad blockers, denying cookies, and deleting tracking IDs helps you regain privacy control.

Discussion Guidelines

  1. E2EE Interception: Correct. The company servers only hold the encrypted scrambled bytes; they do not hold your private keys. They cannot decrypt them. The only way is to access the physical phone, backup logs (if unencrypted), or bypass security at the endpoint.
  2. Complexity constraints: Forcing exactly 8 characters limits entropy. The total combinations are tiny compared to a 20-character passphrase. Furthermore, humans follow identical patterns (like capitalizing the first letter and putting "1!" at the end), which hacking programs exploit.

Mobile & Platforms

Under the Screen: Permissions, Privacy, and App Ecosystems

Key Objectives

  • Contrast Native compiled applications with Browser Web Apps.
  • Understand the OS Sandbox and Hardware API boundary.
  • Learn how ad platforms use Advertising IDs to track you.

Lesson 8 Intro

In this lesson, we study mobile security architectures. Why do apps request permissions, how does sandboxing work, and how can we audit our own smartphones?

Press Down to explain native vs web apps.

Native vs. Web Applications

Where the code runs and what it can touch

Native Applications

Written specifically for the OS (Swift/Kotlin), compiled to machine code. Downloaded from store. Deep access to hardware features (GPS, camera, contacts) and run in the background.

Web Applications

Written in HTML/JS, run inside the browser. No download required. Highly restricted by the browser's sandbox. Cannot access contacts, files, or background services without API approval.

Comparison Details

Explain that Native apps have faster performance because they run directly on the processor, but they have broader security risks. Web apps are safer because they are sandboxed inside the web browser.

Sandboxing & Hardware APIs

System borders that protect your data

Sandboxed Environment

Mobile operating systems isolate apps. An app lives in its own "room". It cannot view or edit files belonging to other apps unless you grant permission.

Hardware APIs

If an app wants to use the camera, check GPS coordinates, or scan Bluetooth, it must request access from the OS via **APIs** (Application Programming Interfaces).

Hotel Metaphor

Mobile sandboxing is like a secure hotel. Apps are guests. In early desktop computing, apps got master keys to all rooms (could search all files). In sandbox hotels, guests are locked in their rooms. If they need to use the camera, they ask the front desk (OS) which prompts the owner (you) for approval.

iOS vs. Android Security

Different architectural philosophies

iOS: Walled Garden

Stricter Apple review process. Blocks app installation from outside the App Store by default (no sideloading). Less customization, but lower risk of downloading malware.

Android: Open Ecosystem

Open-source foundation. Allows alternative app stores and direct installation of installation packages (`.apk`). Highly customizable, but higher risk of malware if download guidelines are ignored.

Security Trade-offs

Explain that both platforms are highly secure, but use different philosophies. Apple prioritizes centralized control and security; Google prioritizes open customization and developer flexibility.

App Tracking & Ad Profiles

How free applications make money

Advertising ID

A unique ID assigned to your phone (IDFA on iOS, Ad ID on Android). Apps send this ID to ad networks, letting them track what you look at across different apps.

Profile Compilation

If you look at shoes on Amazon, read about hiking on Reddit, and check the weather, trackers link these activities to your Ad ID to target you with sneaker ads.

App Monetization

Explain: *"If you aren't paying for the product, you are the product."* targeted ads are how free app makers monetize. iOS 14.5 introduced "App Tracking Transparency" (Ask App not to Track), which cost ad networks billions of dollars because users opted out.

Discussion Guidelines

  2. Browser Sandboxing: Browsers are highly hardened sandboxes. They execute javascript and render HTML inside restricted memory threads that cannot access your physical filesystem, launch system processes, or execute local code.

AI as a Bicycle for the Mind

How Large Language Models Work, Prompting, and the Art of Fact-Checking

Key Objectives

Lesson 9 Intro

AI is a daily tool for teens. Today we dismantle the illusion of AI consciousness. We'll show that AIs are probability predictors, and how to verify their output.

Press Down to explain next-token prediction.

Autocomplete at Scale

Next-token prediction mechanics

Probability Engines

LLMs do not lookup facts in databases. They calculate mathematical probability. Given your input, they check their weights (patterns from billions of training pages) to predict the most likely next word fragment.

Training Data Limits

An AI only knows patterns in its training dataset. It cannot "reason" out new logical discoveries; it can only connect existing patterns it has indexed.

Autocomplete Metaphor (Script)

Explain: "Open your phone, type 'I want to eat...', and check the word recommendations. It suggests 'pizza' or 'apple'. It doesn't know what you want; it calculates the most likely next word. LLMs are this model scaled up to massive computers."

What is a Token?

How computers read characters

Word Fragments

AIs don't read words. Text is split into **tokens** (syllables or groups of letters).
• `Antigravity` is split into: `Anti` and `gravity`.
• 100 words represent ~130 tokens.

Numeric Vectors

Every token is mapped to a unique number. The model converts your text to numbers, performs high-dimensional geometry math, and outputs numeric tokens.

Tokenization

Explain that because AIs read tokens, they sometimes struggle with word details (like counting how many letters are in a word, or reversing a word) because they don't see the letters—they only see the numeric token ID.

Why AI Hallucinates

Plausible text vs. Verified facts

Plausibility Priority

The AI is trained to write sentences that *sound natural and correct*. It prioritizes grammatical flow and pattern matching over checking factual records.

The Confident Lie

If you prompt: "Tell me about the inventor X," the AI checks biography patterns and fills details. It doesn't halt to check if X is real; it just predicts the next word.

Hallucination Explanation

This is key: AIs don't have a concept of truth. They have a concept of probability. If a lie has a high probability of sounding correct based on the context, the AI will output it with absolute confidence.

Prompt Engineering

How to get accurate AI output

The Structured Prompt Model

• **Role:** "Act as a senior software developer."
• **Context:** "I am writing a Python script to filter dates."
• **Constraints:** "Do not use external libraries. Output only the code block."
• **Chain of Thought:** "Explain your logic step-by-step before printing the code."

**Few-Shot Prompting:** Provide the AI with 2 or 3 examples of correct input-output formats in the prompt to set the pattern.

Prompting Tip

Explain that "Chain of Thought" (asking the AI to think step-by-step) is a cheat code. It forces the AI to output its working steps. This guides the prediction probabilities, making the final answer much more accurate.

Bicycle for the Mind

Intellectual honesty and tool usage

Bicycle Analogy

Steve Jobs called computers "a bicycle for the mind." A bike doesn't move on its own; you must pedal. But pedaling lets you travel farther and faster. AI is a bicycle—you must pedal it with your own brain.

The Verification Rule

Never copy-paste AI-generated text without reading and checking facts. You are responsible for the final output. If the AI hallucinates, it is **your** mistake for not catching it.

Ethics Discussion

If you submit an essay written by AI, you didn't learn, and you didn't train your own mind. It's like having someone else ride the bicycle for you while you sit on the bench. Use AI to brainstorm, outline, or explain hard concepts, but write the work yourself.

  2. Cognitive training: Writing is not just putting words on a page; writing is structural thinking. Formatting arguments and choosing words builds neural pathways for logical reasoning. Copy-pasting deprives you of this mental exercise.

The Diagnostic Loop: How to Fix Anything with Science

Lesson 10 Intro

Welcome to the final lesson. Troubleshooting is a core tech skill. Today we study the diagnostic loop, and then they will fix a real "broken" computer that you configured.

Press Down to explain the Diagnostic Loop.

The Scientific Method

Solving computer bugs step-by-step

The Diagnostic Loop

  1. **Symptom:** Define the problem. Read the exact error message.
  2. **Scope:** Isolate. (Is it this program or all? this computer or all devices?).
  3. **Hypothesis:** Formulate a testable guess of what is broken.
  4. **Test:** Change **one variable** at a time. Check if the symptom changes.
  5. **Document:** Remember the solution for the future.

Light Bulb Metaphor (Script)

Explain: "You flip your bedroom light switch. Nothing happens. Do you run to the basement and flip the house breaker? No."

"First, you check if the hallway light is working (Scope). Next, you try a working bulb in the lamp (Bulb variable). If the bulb works elsewhere, then the room switch or wall wiring is broken. That is isolating variables."

Network Diagnostic Tools

Checking connection layers

CLI Tools

  • ipconfig /all: Displays local IP address, gateway, and DNS server settings.
  • ping : Tests connectivity. (If `ping 8.8.8.8` works but `ping google.com` fails, DNS is broken!).

Browser DevTools

Press **F12** (or right-click -> Inspect). Check the **Console** tab for code crashes, or the **Network** tab to see if assets (CSS/images) fail to load with 404 or block issues.

Command usage

Show them how ipconfig reveals their local router address (Default Gateway). If their IP starts with 169.254.x.x, explain that their computer failed to get an IP from the router (DHCP failure).

Error Fingerprints

How to search for help effectively

Error Codes

Computers output specific code footprints (e.g., `0x80070005` or `DNS_PROBE_FINISHED_NO_INTERNET`). These codes point to the exact failure point in the OS or network stack.

Search Strategies

Don't search: "my network doesn't work." Search the exact code with terms:
"0x80070005" windows installer permission fix
Filter results by recent date on Reddit or tech forums.

Troubleshooting Wisdom

Explain that no developer knows everything. The best programmers are simply world-class searchers who know how to parse forum answers and match error codes to solutions.

System Management Tools

Viewing hardware and active processes

Device Manager

Lists all physical hardware drivers. A yellow warning triangle indicates a driver conflict or hardware fault. You can disable, enable, or update device drivers here.

Task Manager

Displays CPU, RAM, and disk utilization. You can identify which background app is hogging resources and force-terminate frozen programs (End Task).

System Controls

Show them how to open Task Manager (Ctrl + Shift + Esc). This shows what is happening on the computer right now, letting you diagnose background issues.
